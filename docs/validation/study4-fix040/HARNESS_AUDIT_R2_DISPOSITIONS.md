| **R2-B4** emitted-claim clarification relaxes the removal gate | **Adopt; ruling A2 withdrawn.** The maintainer's A2 ruling was wrong: enlarging the removal denominator with dropped sibling claims can dilute the success share. The removal gate uses exactly the protocol's **genuine-deletion** population: baseline hits with **no** counterpart at the same occurrence (no retained claim at the same span, no resolved span change, no reassignment). A dropped claim at a span that keeps another candidate claim is **not** a genuine deletion; it is an affected row whose loss is accounted for by occurrence retention (STRICT: the dropped claim is lost if it was correct; LENIENT/LIST_LENIENT: retained if a resolved, definitely successful sibling remains). No emitted-claim removal screen is added; J = 68 unchanged. The clarification document is corrected accordingly; it must not claim conservatism it does not have. Tests: the audit's census dilution example and a no-other-gate-fails example. |

Mandatory manifest schema and output inventory. Bind all stage source hashes and the runtime identity, including model/package artifact hashes (spaCy model package files, installed lexinspect wheel/source), to the freeze. ## SHOULD-FIX

| Finding | Disposition |
|---|---|
| **R2-S1** shared-reference completion | **Adopt per-row exactness; declare the cell-total relaxation.** Per row, a resolved counterpart sharing the baseline's reference variable gives loss identically zero, for any number of variables (analytic, no enumeration or fallback). Cell totals are the sum of per-row exact extrema; this is a **conservative relaxation** (it can only raise U_loss), stated as such in the clarifications instead of claiming the joint highest-consistent completion. Tests with >12 variables and the coupled x→y / y→x example (documented as conservative). |
| **R2-S2** dry-run resume | Adopt: resume identity includes source digest, commit, harness hashes, environment and settings; refuse mismatches before rewriting anything. The final committed-candidate dry run uses a fresh unique directory. Regression for same-bytes, new-commit resume. |
| **R2-S3** replay of fetch failures | Adopt: an ordered request/failure ledger (URL, cache key, sequence, failure class and message) is archived; replay verifies it and reproduces the archived failure without a request; original retrieval dates are archived, not inferred from mtime. Replay requires authenticated raw responses **and** identical decision logs. Tests for network failure, successful-but-ineligible body, restored mtime, both source types. |
| **R2-S4** power reporting | Adopt: (1) remove the inverse inference ("inconclusive signals ≥1% loss"); (2) call the greedy value "a feasible value found by the declared greedy search", with its exact loss/removal counts; (3) add the module-calibrated informational scenario: per-module total losses set to the S8 development definite-loss rates (metadiscourse LENIENT 3/690 and STRICT 2/621; PHRASE 1/202 and 1/201), plus a second variant at the S8 upper rates (MD LENIENT 31/690, STRICT 6/621), coherent populations, all-gates / module / gate frequencies with MC intervals. Label target λ separately from realised loss; flag nominal-zero scenarios with realised losses. "All gates" means all statistical gates conditional on a valid procedure. No threshold, n, allocation or grid changes. |
| **R2-S5** runbook | Adopt: defaults point to `docs/validation/study4-fix040/`; rewrite the freeze checklist as a concrete runbook incorporating every Addendum ruling; explicit public allowlist of committed files and a private archive (with SHA-256 receipts recorded publicly) for restricted materials (packaged candidate data, hit payloads, units/items/key, anything containing PHRASE glosses, examples or sense inventory text). Fix `verify --ledger-md` and `--registry` arguments. Replay requires raw/log authentication. Retry/Flash derivations and session packages archived before delivery. The numeric seed and absolute paths are maintainer actions at freeze: the runbook leaves exactly those placeholders and the generated `command.txt` resolves them. |
