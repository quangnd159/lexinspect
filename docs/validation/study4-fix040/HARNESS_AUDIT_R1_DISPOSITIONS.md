# Dispositions of Sol harness audit r1 (sol_harness_audit_r1.md)

2026-10-17. Maintainer decisions, made before any fix-check text was collected and before any label. Frozen inputs (`build.py`, `analyse.py`, `estimators.py`, `frame.py`, `batches.py`) stay byte-identical; every change is in the `fixcheck` wrapper, its tests, or prospective documentation.

## BLOCKING

| Finding | Disposition |
|---|---|
| **B1** plan does not bind collection | **Adopt.** Split *plan* and *execute*. `collect --plan-only` writes an immutable round package (`freeze_record.json`) containing: the literal execution argv (as it will be run, excluding the planning flag), numeric seed, full pool inventory with hashes, cache policy and initial cache inventory, canonical dev manifest identity, earlier-round identities (round 2), candidate full commit id + source tree digest, environment identity (uv.lock hash, Python, spaCy + model versions), ledger Markdown hash and `ledger_components.json` hash, protocol hash, harness and frozen-source hashes. Execution (`collect --execute --freeze-record <path>`) recomputes every one of these from the actual invocation and refuses on any mismatch before any fetch. It also requires: a clean tracked working tree at the declared commit; `src/lexinspect` byte-equal to that commit; and an archive receipt: the freeze record committed and present on a pushed remote ref (verified locally with `git merge-base --is-ancestor <commit> <remote-ref>` and `git cat-file` — no network call). `prepare-candidate` snapshots from `git archive <commit>`, never the working tree. The planned `command.txt` is never overwritten; execution metadata goes to `execution.json`. Dry-run facilities stay, explicitly flagged ineligible. Negative tests change each bound input independently. |
| **B2** acceptance without procedure/history | **Adopt.** Production `accept` consumes one round package and verifies the hash chain collection → run → baseline verification → diff → selection → assignment → session deliveries → labels/retry/Flash → verification. Round number, candidate identity and component identities come from the package, not the CLI. Any missing/failed link, a shortfall, an unverified pinned baseline (both `--pinned-src` and `--pinned-checkout` must verify against full dec79bc commit and environment), a missing pre-label decision plan, or ledger mismatch ⇒ `inconclusive` with the problem listed; never `pass`. Dry-run packages may compute a mathematical result but are stamped `production_eligible: false`. Add an append-only round registry (`round_registry.jsonl`, committed): one finalized decision per (candidate, round); round 2 requires a registered round-1 non-pass, a separately frozen revised candidate keeping the original family identities with a reviewed disposition for any narrowing, a disjoint collection and distinct seed; after round 2 only terminal outcomes (ship, revert to 0.3.3, amendment). Idempotent recomputation of identical inputs is allowed; new labels/seeds/candidates under used identities are refused. No pooling or subset rescue. |
| **B3** Flash and retry provenance | **Adopt.** At acceptance, recompute `needs_adjudication` from the exact final primary A/B files and require set equality with the Flash assignment, plus matching assignment, batch and input hashes. Distinguish delivered-but-non-vote from never-delivered. Require the first-pass files, the retry manifests, at most one retry per role, and a verified deterministic merge; keep raw responses and validation logs. Wrappers around the frozen validator/merge only. Tests: stale Flash set, omitted/extra ids, altered primary, skipped retry, second retry, altered definite label. |
| **B4** crosswalk: overlap ≠ retention; claim deletion ≠ occurrence loss | **Adopt; A2 reconciled.** The crosswalk separates two things: <ol><li>**Emitted-claim disposition** (unchanged/removed/reassigned/span/multiplicity), one row per baseline emitted hit — this drives the *removal gate*. Ruling A2 stands **only** for the removal gate: a dropped claim at a span that keeps another claim is a removed emitted claim. This is the protocol's "genuine-deletion subset" read as emitted claims, conservative against the candidate, and is recorded as a prospective clarification (below).</li><li>**Occurrence-retention links**, used only for loss accounting (U_loss, definite/possible loss). Every baseline row links to all retained counterparts that demonstrably concern the same occurrence, *including siblings already matched for another claim*. For LENIENT/LIST_LENIENT, a resolved, definitely successful sibling at the same occurrence establishes retention (protocol: "a supported occurrence in the same target inventory"). For STRICT the corresponding claim is required.</li></ol>**Resolution rule for span changes (frozen):** a span change is *resolved* only if baseline and counterpart have the same canonical marker/expression (metadiscourse: same normalised marker string and same category, or the reassignment target; PHRASE: same rank) and the candidate span contains the baseline marker's head token or vice versa. Geometric nesting alone never resolves. Everything else is unresolved and takes worst-case loss. Tests: the audit's `I believe`/`I` case (unresolved) and the same-span hedges/boosters sibling case (LENIENT retention, no definite loss), each including a configuration where the old rule would have produced a breach certificate. |
| **B5** power and attainable bounds | **Adopt.** Replace the simplified calculations with a simulation through the real acceptance path: coherent finite-population references per payload (shared across frames), the actual crosswalk including unresolved links, worst-case completion, the registered samples, then `accept`'s decision. Report per-gate power and the probability that **all** required gates pass, with Monte Carlo intervals, and feasible attainable bounds that respect shared-payload constraints. Scenarios: the declared loss grids × the observed unresolved-link structure (all unresolved resolve to loss; none do; development-share proportion). Keep the old numbers only if labelled "optimistic marginal benchmark". Frozen before labels; nothing chosen from check outcomes. **Maintainer acceptance, recorded now:** the gates are deliberately strict; an inconclusive result means 0.4.0 does not ship on that round (round 2 or revert to 0.3.3). The maintainer accepts the resulting chance of inconclusiveness prospectively and will not seek a label-driven amendment. |
| **B6** redirects break the archive | **Adopt.** Wrap the frozen fetch to record, per returned selection, requested title, URL, cache path, pageid and revid; hash that exact response file; replay uses the same mapping. No renaming, no refetch. Tests: normalised title, redirect title, two titles → one page, two cached revisions. |
