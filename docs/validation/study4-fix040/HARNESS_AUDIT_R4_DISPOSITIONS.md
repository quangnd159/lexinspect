# Dispositions of Sol harness audit r4 (sol_harness_audit_r4.md)

2026-10-17. Maintainer decisions, before any fix-check text or label. All adopted per the audit's "Exact fix"; no gate, n, allocation or J change.

- **R4-B1 (durability on macOS).** Adopt. Platform-aware durable barrier: on Darwin, `fcntl(fd, F_FULLFSYNC)` on the start record, the journal and the parent directory (directory via an `O_RDONLY` descriptor) after each write, before returning permission to fetch; on any failure of the full barrier refuse before the first request (no silent downgrade). On Linux: `fsync` file + `fsync` directory (documented equivalent). Darwin regression instrumenting call order; fault-injection test where the full barrier fails and no request is reached. The runbook's power-loss promise stays, now backed by the barrier, with the residual dependence on the storage device honouring full flush disclosed.
- **R4-S1 (procedure_failure path).** Adopt. New `register-failure` command: binds canonical reservation, authenticated freeze/receipt, immutable start record, abort record/journal/cache evidence, a failure-archive hash and a complete-input identity; produces `procedure_failure` without labels or arithmetic; atomic and idempotent append; later normal acceptance for that round refuses permanently. **Exposure inventory for an interrupted round 1:** every source identity whose request appears in the journal (requested, whether or not it succeeded), plus every cached body in the round cache, plus every listing entry selected before the interruption, is excluded from round 2. If the journal fails integrity validation or the exposure cannot be reconstructed, round 2 refuses and only the terminal routes remain (revert to 0.3.3 or reviewed amendment). Round-2 planning authenticates the failure evidence. A failed round 2 permits only terminal outcomes. Integration tests: hard exit → register-failure → restart refusal → disjoint round 2; and the terminal case; no network, no real labels.
- **R4-S2 (journal integrity).** Adopt: state-machine validation exactly as the audit specifies (request(i) then outcome(i), strictly increasing seq, two event names only, identity equality across pair and final fetch log, no trailing request for a completed collection; the failure validator allows one final unmatched request); malformed/truncated lines are integrity problems; `append_fsync` loops over short writes. Tests for the three counterexamples, duplicates, short write and truncation.
- **R4-S3 (publication scan).** Adopt. The overlapping 21-character illustration in the `src/lexinspect/_context.py` comment was replaced by the maintainer with independently worded text (comment only; no behaviour change). The fragment scan is extended to the entire intended publication set (candidate source and tests, harness and tests, ledger, all dispositions/rulings copies, protocol, clarifications, runbook, delivery spec), as a test and in the runbook. No exemption mechanism.
- **R4-M1.** Adopt: replace the `$FIX` shortcut with a shell function.

## Addendum: maintainer rulings on HARNESS_R7_SUMMARY.md (2026-10-17)

1. **Registry durability.** Registry appends (reservation, decision, terminal) use the same platform barrier as the execution claim (Darwin `F_FULLFSYNC` on file and directory; refuse on failure).
2. **Completed but unlabellable collection** (shortfall, or any post-collection procedure step that cannot complete before labels). It is closed with `register-failure` as `procedure_failure`, a non-pass that consumes the round, exactly like an interrupted run. Exposure is the full collected text set plus everything in the journal and cache. Round-1 continuation and round-2 terminal rules are identical. Accepting with a shortfall stays forbidden.
